> เคยโดน agent ตัวอื่น GANK ตอนกำลังพิมพ์อยู่กลางคัน ใน workflow หลาย agent ของ Herdr ไหม?

คุณรัน PM agent กับ worker อีกสองสามตัวใน Herdr กำลังพิมพ์ prompt ถึง PM ค้างอยู่ครึ่งทาง ปรากฏว่า worker รายงานผลเข้ามาในช่องพิมพ์เดียวกัน กด Enter ครั้งเดียว ทั้งสองข้อความก็ถูกส่งออกไปเป็นคำขอเดียวที่ปนกันมั่ว

**ก่อน**

![ไม่มี Holdback: ข้อความของ worker ถูกพิมพ์ลงใน prompt ของ PM ที่คุณเขียนค้างอยู่ แล้วทั้งสองถูกส่งไปเป็นคำขอเดียวที่ปนกันมั่ว](./media/demo-before.gif)

Holdback ให้ข้อความรอคิวตามลำดับ ข้อความที่ส่งถึง pane ที่คุณกำลังดูจะเข้าคิวอยู่ในแถบเหนือมัน และเข้ามาเมื่อคุณเขียนเสร็จ

**หลัง**

![มี Holdback: ข้อความของ worker รออยู่ในแถบเหนือ pane ของ PM ระหว่างที่คุณเขียนและส่ง prompt ของคุณให้เสร็จ จากนั้นคลิกที่แถบเพื่อส่งเป็นข้อความแยกต่างหาก](./media/demo.gif)

- **ช่องพิมพ์ยังเป็นของคุณ** — ไม่มีอะไรถูกพิมพ์เข้ามาระหว่างที่คุณพิมพ์ ข้อความจะถูกส่งเมื่อช่องว่างแล้วเท่านั้น
- **เห็นว่าใครรออยู่** — แถบแสดงจำนวนข้อความในคิว ผู้ส่ง และคำแรก ๆ ของแต่ละข้อความ
- **รับตอนไหนก็ได้ตามใจ** — คลิกที่แถบหรือกดปุ่มเพื่อดูรายการ ข้อความจะเข้ามาตามลำดับที่มาถึง
- **ข้อความมีลายเซ็น** — เริ่มข้อความด้วย `ชื่อ 💬 ` แล้วแถบจะแสดงว่าข้อความนั้นมาจาก agent ตัวไหน
- **หรือจะไปทำอย่างอื่นต่อก็ได้** — สลับไป pane อื่น คิวจะถูกส่งตามลำดับ
- **pane อื่นไม่ถูกแตะต้อง** — ข้อความที่ส่งถึง pane ที่คุณไม่ได้ดูอยู่จะถูกส่งทันที

## การติดตั้ง

ต้องใช้ Herdr 0.9.3 ขึ้นไป และ Node 18 ขึ้นไป

```sh
herdr plugin install navishachiku/herdr-holdback
```

กำหนดปุ่มใน `~/.config/herdr/config.toml` แล้วโหลดใหม่ด้วย `prefix+shift+r`:

```toml
[[keys.command]]
key = "alt+i"
type = "plugin_action"
command = "herdr-holdback.open"
description = "open the holdback list"

# Notifications are off by default; the queue notice needs this.
[ui.toast]
delivery = "herdr"
```

## ข้อจำกัด

- ถ้าการส่งล้มเหลว การระบายคิวจะหยุดและข้อความที่เหลือยังอยู่ในคิว ไม่มีข้อความใดหาย
- ถ้าโฟกัสออกจาก Herdr ไปทั้งหมด (คุณสลับไปแอปอื่น) จะไม่มีการส่งข้อความจนกว่าโฟกัสจะย้ายไป pane อื่น

### การส่งข้อความ

ทุกอย่างที่ต้องการให้ข้อความเข้าคิวระหว่างที่คุณกำลังดูอยู่ ต้องผ่าน `src/send.mjs`:

```sh
node ~/Project/herdr-holdback/src/send.mjs --to w1:p2 "Task-58/TL 💬 gate 1 reached"
```

ข้อความก่อน ` 💬 ` จะถูกใช้เป็นผู้ส่งในการแจ้งเตือน หากต้องการระบุเอง ให้ส่ง `--from` ผลลัพธ์เป็น JSON หนึ่งบรรทัด: `{"ok":true,"queued":true,"count":2}` เมื่อถูกกักไว้ และ `"queued":false` เมื่อถูกส่งทันที ข้อความที่ส่งถึง pane ที่มี agent จะเข้าผ่าน `herdr agent prompt` ส่วนเทอร์มินัลทั่วไปผ่าน `herdr pane run`

รีโพนี้มีให้แค่คิวกับจุดเข้าใช้งานเท่านั้น การทำให้ agent ของคุณเรียกใช้สิ่งนี้แทน `herdr agent prompt` เป็นหน้าที่ของตัวป้องกันการส่งของคุณเอง

### วิธีทำงาน

| ส่วนประกอบ | หน้าที่ |
| --- | --- |
| `src/daemon.mjs` | คิวที่ทำงานค้างอยู่เบื้องหลัง ตัดสินใจว่าจะเข้าคิวหรือส่งทันที ระบายคิวเมื่อโฟกัสออก และดูแลแถบเหนือ pane ประมวลผลทีละคำขอ |
| `src/on-focus.mjs` | hook `pane.focused` เหตุการณ์ของ Herdr ไม่บอกว่าออกจาก pane ไหน daemon จึงจำโฟกัสก่อนหน้าไว้เอง และตั้งค่าเริ่มต้นจาก `herdr pane list` ตอนเริ่มทำงาน |
| `src/open.mjs`, `src/list.mjs` | การทำงานของปุ่มและรายการแบบป๊อปอัป |
| `src/send.mjs` | จุดเข้าใช้งานสำหรับผู้ส่ง |

เมื่อข้อความเก่าที่สุดรอมา 5 นาทีและช่องพิมพ์ว่าง คิวทั้งหมดจะถูกส่งตามลำดับ โดย daemon ตรวจสอบทุก `check_interval_seconds` (ดู การตั้งค่า)

คิวเก็บอยู่ในไฟล์ ดังนั้น daemon ที่รีสตาร์ทจะทำต่อจากจุดที่หยุด สถานะอยู่ที่ `~/.local/state/herdr/plugins/herdr-holdback/` (`queue.json`)

### การตั้งค่า

การรันครั้งแรกจะเขียน `config.toml` ลงในไดเรกทอรีตั้งค่าของปลั๊กอิน (`herdr plugin config-dir herdr-holdback`):

```toml
check_interval_seconds = 30
```

ความถี่ที่ daemon ตรวจว่า pane ที่คุณกำลังดูมีข้อความที่รอมา 5 นาทีหรือไม่ ค่าเริ่มต้น 30 วินาที รีสตาร์ท daemon เพื่อให้การเปลี่ยนมีผล ส่วนเวลารอ 5 นาทีเองตั้งค่าไม่ได้
